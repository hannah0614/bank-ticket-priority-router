# Saved evaluation results

These are the unchanged actual results from the final 200-ticket run uploaded by the author. `baselines_final_200/` contains 400 predictions for two frozen systems; `llm_final_200/` contains 200 real model predictions. Each system has exactly one prediction per test ticket. Model, prompt, threshold, dataset and provider provenance are retained in manifests and records. No API key is stored here.

`metrics.json` in each directory is generated by the original `ticket_router.evaluate` against the reviewed gold. Macro-F1 averages High/Medium/Low. Escalate is a miss in strict recall and accuracy; High-or-Escalate recall is separate. Wrong raw among abstained is 0/1 in this run. Metric definitions, commands and critique are in [`../docs/EVALUATION.md`](../docs/EVALUATION.md).

`analysis/` contains derived files, generated offline by `eval_saved.py` from these predictions: metric comparison, LLM confusion counts, 11 final non-match rows, one abstention row, recorded cost and latency. Ten of the 11 non-matches are raw mistakes; the remaining row had a correct raw Medium label and escalated. The derived files are analysis, not another model evaluation.

Run `python eval_saved.py` from the repository root to reproduce the numbers without a key. New analysis is written to `reruns/saved_analysis/`. New baseline or live final runs go under `reruns/final_200/`. Live UI jobs go under `demo_runs/`. The supplied final runner rejects writes inside `results/`, and the app reads these submitted metrics without replacing them with demo scores.
